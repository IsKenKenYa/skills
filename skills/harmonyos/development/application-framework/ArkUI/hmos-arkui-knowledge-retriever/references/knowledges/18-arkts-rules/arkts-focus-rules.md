# HarmonyOS 焦点事件规则指南

> 本文档聚焦焦点系统的行为规则、约束条件和注意事项，供开发者在实现焦点逻辑时查阅。

---

## 1. 焦点基础规则

### 1.1 焦点唯一性

- 应用界面上同一时刻只有一个组件处于获焦状态
- 从根节点到获焦组件的路径上所有节点形成焦点链，均处于获焦状态

### 1.2 焦点激活态

焦点框（激活态）的显示与获焦是两个独立概念：

| 规则 | 说明 |
|------|------|
| 获焦 ≠ 显示激活态 | 组件获焦后，焦点框仅在应用处于"激活态"时才显示 |
| 显示激活态 → 必定获焦 | 显示焦点框的组件一定是当前获焦组件 |
| 子组件优先显示 | 同一时间只显示一个焦点框，子组件优先 |

**进入激活态：**

- 按下外接键盘 **Tab 键**（首次 Tab 仅激活，不移动焦点）
- 调用 `FocusController.activate(true)`

**退出激活态：**

- 调用 `FocusController.activate(false)`
- 发生触屏点击或鼠标左键点击

### 1.3 层级页面规则

层级页面包括：Page、全屏/半模态页面、Dialog、Menu、Popup、NavBar、NavDestination。

| 规则 | 说明 |
|------|------|
| 焦点跟随 | 层级页面首次展示后立即抢占焦点 |
| 走焦范围限制 | 焦点在层级页面内部时，无法通过键盘转移到外部 |
| Popup 例外 | Popup 在 `focusable` 为 false 时不具备焦点跟随特性 |
| NavBar/NavDestination | 没有走焦范围限制，走焦范围与首个父层级页面相同 |

### 1.4 根容器默认焦点

- 层级页面首次创建时，焦点默认位于根容器
- 可通过 `defaultFocus(true)` 自定义默认获焦节点
- 焦点在根容器时，首次 Tab 键进入激活状态并按传递规则向下传递

---

## 2. 焦点传递规则

- 焦点链上的所有组件都处于获焦状态
- 组件获焦时，递归传递获焦状态给第一个子组件，直到叶子节点
- `requestFocus` 指定容器时，焦点会转移到该容器的第一个可获焦子节点

---

## 3. 走焦规则

### 3.1 主动走焦

| 方式 | 规则 |
|------|------|
| **Tab 键** | Z 字型遍历所有叶子节点，循环走焦 |
| **Shift+Tab** | 与 Tab 键相反 |
| **方向键** | 十字型移动策略，由容器走焦算法决定 |
| **requestFocus** | 主动将焦点转移到指定组件，可跨层级页面，不可跨窗口 |
| **clearFocus** | 清除当前层级页面焦点，焦点回到根容器 |
| **focusOnTouch** | 点击获焦，容器优先转移给上一次获焦的子组件 |

**按键走焦前提：**

- 应用需处于焦点激活态
- 仅在当前获焦的层级页面内进行
- 子组件处理按键走焦事件时，父组件不再介入

### 3.2 被动走焦

| 触发场景 | 行为 |
|----------|------|
| 组件删除 | 先尝试相邻兄弟组件（先向后、再向前），否则通知父组件 |
| 属性变更 | `focusable`/`enabled` 设为 false 或 `visibility` 设为不可见时自动转移 |
| 层级页面切换 | 当前页面释放焦点，新页面按预设逻辑获焦 |

---

## 4. 走焦算法规则

### 4.1 线性走焦（默认）

适用于 Row、Column、Flex 等单方向布局容器。

| 规则 | 说明 |
|------|------|
| 顺序依赖 | 走焦顺序基于节点树挂载顺序，与界面布局位置无关 |
| Tab 键 | 按挂载顺序依次遍历 |
| 方向键 | 与容器方向垂直的方向键不响应 |
| 边界处理 | 首尾子节点拒绝反方向走焦 |

- **Column 容器**：上下键走焦，左右键不响应
- **Row 容器**：左右键走焦，上下键不响应

### 4.2 投影走焦

适用于 RelativeContainer、配置 wrap 的 Flex。组件排列需非常规整。

| 规则 | 说明 |
|------|------|
| 方向键 | 判断投影重叠面积 → 选择面积不为 0 中距离最短的组件 |
| Tab 键 | 先按方向右判定 → 模拟下移后按方向左判定 |
| Shift+Tab | 先按方向左判定 → 模拟上移后按方向右判定 |

**注意：** 大小不一旦存在交叠关系时，走焦顺序可能与预期不符。需要明确走焦顺序时，建议使用 Column/Row。

---

## 5. 组件获焦能力规则

### 5.1 获焦能力分类

| 类型 | 说明 | 示例组件 |
|------|------|----------|
| 默认可获焦 | 有交互行为，无需设置 | Button、Checkbox、TextInput |
| 有能力但默认不可获焦 | 需设置 `focusable(true)` 使能 | Text、Image |
| 无获焦能力 | 即使设置也无效 | Blank、Canvas、Circle、Rect、Path |

### 5.2 容器获焦规则

- 容器作为叶子节点时，即使设置 `.focusable(true)` 也无法获焦
- 需添加具备获焦能力的子组件，或配置 `onClick` / Tap 手势
- **隐式可获焦**：无 focusable 属性的容器，配置 `onClick` 或单指单击 Tap 手势后可获焦

### 5.3 动态失焦规则

组件处于获焦状态时，将其 `focusable` 或 `enabled` 设为 false，会自动失焦，焦点按被动走焦规则转移。

---

## 6. 容器焦点框规则

容器组件本身无法绘制焦点框，需满足以下条件：

1. 容器内部没有可获焦子节点
2. 容器配置有 `onClick` 或单指单击 Tap 手势
3. 容器本身未设置 `focusable` 属性，或设置在 `onClick`/Tap 手势之后

---

## 7. tabStop 规则

| 规则 | 说明 |
|------|------|
| Tab 键 | 焦点在 tabStop 容器之间切换 |
| Enter 键 | 焦点进入容器，转移到第一个可获焦节点 |
| ESC 键 | 焦点退回到不超过当前层级页面根容器的上一个 tabStop 组件 |
| 空格键 | 响应容器的 `onClick` 事件 |
| 嵌套限制 | tabStop 容器不允许嵌套超过 2 层 |
| 根容器 | 不建议在根容器上配置 tabStop |

---

## 8. 默认焦点规则

### 8.1 defaultFocus

- 仅用于层级页面（Page、NavDestination、NavBar、PopUp、Dialog 等）
- 若多个组件设置了 `defaultFocus(true)`，以组件树深度遍历找到的第一个为准
- **不可与 FocusPriority 混用**，同时配置行为未定义

### 8.2 groupDefaultFocus

- 必须与 `tabIndex` 联合使用
- 仅在容器首次获焦时生效
- 若有多个组件设置，以组件树深度遍历找到的第一个为准

### 8.3 整体获焦 vs 非整体获焦

| 类型 | 说明 | 场景 |
|------|------|------|
| 整体获焦 | 容器自身作为叶节点获焦，再转移到子孙组件 | 层级页面切换、Navigation 路由切换、焦点组走焦 |
| 非整体获焦 | 某组件作为叶节点获焦，祖先节点跟着获焦 | TextInput 主动获焦、Tab 键非焦点组走焦 |

**整体获焦焦点链规则：**

1. 层级页面首次获焦 → `defaultFocus` 节点获焦，未配置则停留在根容器
2. 层级页面非首次获焦 → 上次获焦的节点获焦
3. 焦链上有优先级配置 → 优先级大于 `PREVIOUS` 时由最高优先级组件获焦，否则由上次获焦节点获焦

---

## 9. 自定义走焦规则

### 9.1 nextFocus

- 配置了 `nextFocus` 的组件只按设定顺序走焦
- 未设置或目标不存在的方向仍使用默认规则

### 9.2 tabIndex

- `tabIndex > 0` 的组件按值从小到大循环走焦
- **不可与 focusScopeId 同时设置**
- 不建议用负数控制获焦能力，应使用 `focusable`
- `tabIndex` 仅控制 Tab 键，方向键需使用 `nextFocus`
- 含有 UiExtension 组件的层级页面使用 `tabIndex` 会导致走焦错乱

**容器 tabIndex 规则：**

- 容器内组件都未获焦过 → 走到第一个可获焦组件
- 有获焦过的组件 → 走到上次获焦的节点

---

## 10. 焦点组规则

| 规则 | 说明 |
|------|------|
| 不可嵌套 | 焦点组不可嵌套、不可重复配置 |
| 不可与 tabIndex 混用 | 焦点组不能和 `tabIndex` 混用 |


---

## 11. 焦点与按键事件规则

| 场景 | 行为 |
|------|------|
| `onClick` / `TapGesture` | 回车、空格触发时**默认不冒泡** |
| `onKeyEvent` | **默认冒泡**，会触发父组件回调 |
| 同时存在 `onClick` 和 `onKeyEvent` | 回车、空格触发时两者都响应 |
| API version 18+ | 获焦组件仅在焦点激活态时响应 `onClick` |

**TextInput 特殊行为：** TextInput 对方向键有独有处理，无法用方向键直接走出。

---

## 12. 通用注意事项

- 设置 `focusable`、`enabled` 为 false 或 `visibility` 为 Hidden/None 时，**不影响自定义组件的子组件获焦**
- 组件主动获焦不受窗口焦点控制
- 绘制焦点激活态的组件的 `zIndex` 默认被抬升至 `INT_MAX`，不再绘制时恢复
- 通过 `requestFocus` 请求焦点时，若容器配置了 `tabStop` 焦点能停留在容器上，未配置则直接到目标组件
- 设置 `clip(true)` 的组件会裁剪超出自身边界的焦点框，导致焦点框不可见。需关注焦点框是否超出组件范围，必要时关闭裁剪或调整焦点框绘制位置

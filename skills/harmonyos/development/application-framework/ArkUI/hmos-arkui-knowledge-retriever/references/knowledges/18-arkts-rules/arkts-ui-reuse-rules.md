# ArkTS 自定义组件复用规则要求

## 1. 概述

组件复用是一种优化 UI 性能的机制。当自定义组件从组件树上移除时，会被存入缓存池，后续在创建相同类型的组件节点时，将优先复用缓存池中的组件对象，从而避免重复创建和销毁，提升性能。

**两套复用体系：**

| 体系 | 装饰器 | 配套组件装饰器 | API 版本 |
| --- | --- | --- | --- |
| V1 组件复用 | `@Reusable` | `@Component` | API version 10+ |
| V2 组件复用 | `@ReusableV2` | `@ComponentV2` | API version 18+ |

**核心原理：** 被复用装饰器标记的自定义组件在从组件树中移除时（包含视图节点、组件实例和状态上下文）将被放入其**父自定义组件**（最近的祖先**自定义组件**，即被 `@Component` / `@ComponentV2` 装饰的 struct，**而非系统组件**如 `List`/`ListItem`/`Column` 等）的缓存池中。后续创建新自定义组件节点时，将优先复用缓存池中的节点，从而节约组件重新创建的时间。

**关键推论 — 跨容器复用：** 由于缓存池归属"父自定义组件"而非"直接父节点"，**同一父自定义组件下的多个不同容器（如多个 `List` / `Grid` / `Column`）中的同名可复用组件共享同一个缓存池，可相互复用**。例如某页面（`@Entry @Component` 装饰的父自定义组件）内有两个 `List`，分别通过 `LazyForEach` 渲染相同的 `@Reusable` 子组件：第一个 `List` 中滑出屏幕被回收的子组件实例，会被放入页面级缓存池，第二个 `List` 创建新项时可直接复用该实例，无需重新构造。

> 注意：缓存池的归属判定**只认自定义组件**。若可复用组件的直接父链路上没有自定义组件（仅有系统组件），则会向上继续查找，直到遇到最近的祖先自定义组件为止。

**默认复用池的局限与全局复用池（API 26+）：** 默认复用池仅存在于父组件中，当复用组件的父组件被销毁或切换时（如 `if/else` 分支切换不同子组件），缓存池随之销毁，导致跨父组件无法复用。从 API version 26.0.0 起，可在任意 `@Component` / `@ComponentV2` 上声明**全局复用池**（通过 `reusePool` + `poolAccepts` 配置），优先级高于与父组件绑定的默认复用池，详见第 8 节。

## 2. V1 与 V2 总览对比

| 对比项 | @Reusable（V1） | @ReusableV2（V2） |
| --- | --- | --- |
| 装饰对象 | `@Component` | `@ComponentV2` |
| 复用标识 | `.reuseId('groupId')` | `.reuse({ reuseId: () => 'groupId' })` |
| `aboutToReuse` 参数 | 有参数 `params: Record<string, Object \| undefined \| null>`，需手动赋值 | **无参数**，状态变量自动重置 |
| 递归调用子组件 | 回收/复用时递归调用子组件生命周期，与子组件是否被标记无关 | 同 V1 |
| 冻结机制 | 需手动开启 `freezeWhenInactive` | **自动冻结**，回收期间不响应更新 |
| 状态变量重置 | 不自动重置，需在 `aboutToReuse` 中手动赋值 | **自动重置**所有状态变量、`@Computed`、`@Monitor` |
| 无子组件时 | 无任何子组件时不触发 `aboutToRecycle`/`aboutToReuse`，有原生子组件即可触发 | 同 V1 |
| ComponentContent | 不支持，会导致 crash | — |

## 3. 生命周期

### 3.1 生命周期总览

| 回调 | 触发时机 | V1 参数 | V2 参数 |
| --- | --- | --- | --- |
| `aboutToRecycle` | 组件从组件树移除，被放入缓存池 | 无 | 无 |
| `aboutToReuse` | 组件从缓存池取出，重新加入组件树 | `params: Record<string, Object \| undefined \| null>`（构造参数） | **无参数** |

### 3.2 递归特性

回收和复用时具有递归调用子组件生命周期的特性：

- **回收时递归：** 会递归调用其所有子组件的 `aboutToRecycle` 回调。
- **复用时递归：** 会递归调用其所有子组件的 `aboutToReuse` 回调。
- **与子组件是否被复用装饰器标记无关：** 即使子组件没有被标记，其 `aboutToRecycle` 和 `aboutToReuse` 也会被递归调用。
- **递归直到遍历完所有子组件。**

### 3.3 无子组件时不触发回收和复用

当复用装饰器标记的自定义组件没有任何子组件（包括原生子组件和自定义子组件）时，不会触发回收（`aboutToRecycle`）和复用（`aboutToReuse`）的生命周期回调。只要有原生子组件（如 `Column`、`Text`、`Image` 等）或自定义组件子节点，即可正常触发回收和复用。

## 4. 组件结构一致性与 reuseId

### 4.1 复用前后应保持组件结构不变

复用前后应保持组件的结构不变。结构变化会在复用过程中创建或销毁子组件，降低复用效率和性能，甚至造成应用行为异常。

对于复用过程中创建的子组件，框架会**依次调用 `aboutToReuse` 和 `aboutToAppear`**。在调用 `aboutToReuse` 时，由于 `aboutToAppear` 未执行且子组件未创建，依赖 `aboutToAppear` 执行结果或子组件状态的操作会引起预期外行为。

### 4.2 使用 reuseId 区分不同结构

针对组件结构存在差异的场景，必须通过设定不同的 `reuseId` 来进行区分。

| 体系 | 复用标识写法 |
| --- | --- |
| V1 | `ReusableComponent().reuseId('ReuseA')` |
| V2 | `ReusableV2Component().reuse({ reuseId: () => 'ReuseA' })` |

### 4.3 reuseId 分类策略

`reuseId` 用于标记自定义组件复用组。相同 `reuseId` 的组件在同一复用组中复用，单个复用组件无需设置 `reuseId`。

| 问题 | 原因                          | 解决方案                                  |
| --- |-----------------------------|---------------------------------------|
| 分类过粗 | 未根据 if-else 分支设置差异化 reuseId | 根据组件结构特征为不同类别配置独立 reuseId             |
| 分类过细 | 为每个数据项分配唯一 ID，缓存池被过度拆分      | 将结构相近的列表项合并到同一类型，通过 visibility 显隐属性切换 |
| 未设置 reuseId | 结构不同的同名组件共用默认复用组            | 对结构有差异的同名组件显式设置 reuseId               |

## 5. V2 特有机制

### 5.1 复用阶段的冻结

V2 组件被回收时会**自动进入冻结状态**（V1 需手动开启 `freezeWhenInactive`），不需要开发者手动操作。

| 阶段 | UI 刷新 | @Monitor 回调 | @Computed 重新计算 |
| --- | --- | --- | --- |
| `aboutToRecycle` 中（冻结） | 不触发 | 不触发 | 不触发 |
| 回收期间 | 不触发 | 不触发 | 不触发 |
| `aboutToReuse` 起（解冻） | 正常触发 | 正常触发 | 正常触发 |
| 解冻后补刷新 | **不会补刷新**冻结期间的变更 | — | — |

**混用场景冻结规则：** V1 组件根据 `freezeWhenInactive` 决定；V2 组件自动被冻结。

### 5.2 复用前的状态变量自动重置

V2 在复用前会**自动重置**组件中的状态变量以及相关的 `@Computed`、`@Monitor`。所有 V2 自定义组件（无论是否被标记 `@ReusableV2`）都会经历此重置过程。重置按变量在组件中**定义的顺序**依次进行。

| 装饰器 | 重置方法 |
| --- | --- |
| `@Local` | 直接使用定义时的初始值重新赋值 |
| `@Param` | 有外部传入则使用外部传入值，否则用本地初始值。`@Once` 变量同样会被重置一次 |
| `@Event` | 有外部传入则使用外部传入值，否则用本地初始值。无初始值则生成默认空实现 |
| `@Provider` | 直接使用定义时的初始值重新赋值 |
| `@Consumer` | 有对应的 `@Provider` 则使用其值，否则使用本地初始值 |
| `@Computed` | 使用当前最新值重新计算。**推荐定义在所使用的变量之后**，避免使用到未重置的值 |
| `@Monitor` | 所有变量重置完成后触发。重置中的变化不触发回调，仅更新 `IMonitorValue.before` |
| 常量（含 `readonly`、未加装饰器） | **不重置** |

**注意事项：**

- 由于冻结机制，在 `aboutToRecycle` 中对状态变量赋值不会被 `@Monitor` 观察到，重置后变量又会被赋予新值，因此在 `aboutToRecycle` 中赋值对状态变量无明显效果。
- 未加装饰器的常量对象包含 `@Trace` 属性时不会被重置，其相关 `@Monitor` 也不会被重置。推荐在复用场景减少使用此类写法。

## 6. 混用规则

### 6.1 V1/V2 混用支持关系

| 描述 | 对应组件类型 |
| --- | --- |
| V1 普通组件 | `@Component` 装饰的 struct |
| V2 普通组件 | `@ComponentV2` 装饰的 struct |
| V1 复用组件 | `@Reusable` `@Component` 装饰的 struct |
| V2 复用组件 | `@ReusableV2` `@ComponentV2` 装饰的 struct |

**混用支持关系表（行为父组件，列为子组件）：**

| 父组件 \ 子组件 | V1 普通组件 | V2 普通组件 | V1 复用组件 | V2 复用组件 |
| --- | --- | --- | --- | --- |
| V1 普通组件 | 支持 | 支持 | 支持 | 不支持，编译报错 |
| V2 普通组件 | 支持 | 支持 | 不支持，编译告警，子组件不创建 | 支持 |
| V1 复用组件 | 支持 | 支持 | 支持 | 不支持，编译报错 |
| V2 复用组件 | 支持 | 支持 | 不支持，编译报错 | 支持 |

**核心规则：** V1 复用组件和 V2 复用组件不能互相包含。

### 6.2 Repeat template 限制

V2 复用组件不能直接用于 Repeat 的 template 中，需嵌套在普通 V2 组件中：

```typescript
// 反例
Repeat(this.arr).template('a', (ri) => {
  ListItem() {
    ReusableV2Component({ val: ri.item }) // 不支持
  }
})

// 正例
Repeat(this.arr).template('a', (ri) => {
  ListItem() {
    NormalV2Component({ val: ri.item })
  }
})

@ComponentV2
struct NormalV2Component {
  @Require @Param val: number;
  build() {
    ReusableV2Component({ val: this.val })
  }
}
```

## 7. 限制条件总结

### 7.1 限制条件详述

**仅用于自定义组件：** `@Reusable` 仅用于 `@Component`，`@ReusableV2` 仅用于 `@ComponentV2`。不可与 `@Builder` 搭配使用。

**状态变量更新限制（V1）：** 子组件的 `aboutToReuse` 中禁止直接修改父组件的状态变量（如 `@Link`），此次修改不会生效。需使用 `setTimeout` 延迟执行：

```typescript
// 反例
aboutToReuse(params: Record<string, Object | undefined | null>): void {
  this.num = -1 * (params.num as number); // @Link 指向父组件，修改不生效
}

// 正例
aboutToReuse(params: Record<string, Object | undefined | null>): void {
  setTimeout(() => { this.num = -1 * (params.num as number); }, 1)
}
```

**不支持 ComponentContent（V1）：** `ComponentContent`（底层是 `BuilderNode`）不支持传入 `@Reusable` 装饰的自定义组件，会导致 crash。

**不建议嵌套使用：** 嵌套使用会导致额外缓存池生成、内存增加、复用效率降低、生命周期管理复杂。当父组件已启用复用时，若子组件内容简单，应取消子组件自身的复用。

**父组件未复用时子组件复用无效：** 父组件在离开屏幕或被销毁时重新创建，子组件及复用池随之销毁。正确做法：提升复用层级，在父组件启用复用，取消子组件复用。

### 7.2 限制条件速查表

| 限制项 | V1 规则 | V2 规则 | 后果 |
| --- | --- | --- | --- |
| 装饰对象 | 仅 `@Component` | 仅 `@ComponentV2` | 不可用于 `@Builder` |
| 状态变量更新 | 子组件 `aboutToReuse` 中禁止修改父组件状态 | 自动重置，无需手动赋值 | V1 修改不生效 |
| 组件结构 | 复用前后需一致 | 复用前后需一致 | 不一致导致性能下降或异常 |
| ComponentContent | 不支持 | — | V1 导致 crash |
| 嵌套使用 | 不建议 | 不建议 | 增加内存、降低复用效率 |
| 父组件复用 | 父组件未复用时子组件复用无效 | 同 V1 | 复用池随父组件销毁而销毁 |
| 无子组件 | 无任何子组件时不触发，有原生子组件即可触发 | 同 V1 | `aboutToRecycle`/`aboutToReuse` 不被调用 |
| Repeat template | — | 不能直接用于 template 中 | 需嵌套在普通 V2 组件中 |

## 8. 全局复用池（API 26+）

### 8.1 适用场景与定位

全局复用池优先级**高于**与父组件绑定的默认复用池，用于解决默认复用池的两大局限：

- **跨父组件复用：** 默认复用池仅存在于父组件中，父组件销毁或 `if/else` 分支切换时池随之销毁，导致同名可复用组件无法跨父组件复用。全局复用池在组件树上层节点声明，可接纳所有子树下的同名可复用组件。
- **精细化管控：** 默认复用池不支持缓存上限、预渲染、池状态查询等能力，全局复用池提供完整管控。

> **API 版本：** 全局复用池从 API version 26.0.0 开始支持，原子化服务同样可用。API 签名与参数详见 [22-arkts-ui-reuse-quick-apis.md](../quick-apis/22-arkts-ui-reuse-quick-apis.md)。

### 8.2 配置规则（硬性约束）

- `reusePool` 和 `poolAccepts` **必须同时提供**，仅指定其一会导致编译错误。
- `poolAccepts` **必须是非空数组**，每项必须是 `@Reusable` / `@ReusableV2` 装饰的自定义组件名；使用普通组件、`@Builder` 函数或非组件类会导致编译错误。
- `@Component` / `@ComponentV2` **最多只能有一个复用池**。
- `reusePool` 和 `poolAccepts` **仅在 `@Component` 和 `@ComponentV2` 上支持**，在 `@CustomDialog` 上不受支持。
- **可复用组件不能在自己的全局复用池中直接接纳自身组件名**，否则编译错误。
- 启用全局复用时**必须额外配置 `freezeWhenInactive`** 参数（取值参考自定义组件冻结功能 V1/V2）。
- 使用preRender预渲染但不被任何池接受的组件（poolAccepts包含）会被创建并立即销毁。仅预渲染池配置为接受的组件。

### 8.3 所有权模式对比

| 模式 | 行为 | 生命周期 | 适用场景 |
| --- | --- | --- | --- |
| `'shared'` | 拥有组件类的**所有实例共享单个池** | 第一个实例创建时建池；最后一个实例销毁时池销毁 | **推荐**，复用率高、内存占用低 |
| `'perInstance'` | 每个拥有组件实例**各自独立持有一个池** | 池与拥有组件实例同生命周期，实例销毁则池销毁 | 需要与特定父实例绑定的场景（如配合 `@Provider` / `@Consumer`） |

**`shared` 生命周期要点：**

1. 第一个实例创建时建池并被引用。
2. 第二个实例创建时复用已存在的池，不新建。
3. 中间实例销毁时池仍被其他实例引用，不销毁。
4. 最后一个实例销毁时池被销毁，所有回收组件一并释放。
5. 后续若再创建拥有组件的新实例，会创建新池。

> **注意：** `shared` 所有权**不是** `static` 类属性。全局复用池通过跨实例引用计数管理，非永久单例。

### 8.4 多级复用池路由规则

当组件树不同级别存在多个全局复用池配置时，每个可复用组件**路由到接受它的最近祖先池**：

- 框架在可复用组件创建或销毁时，会**向上遍历组件树**查找匹配的全局复用池。
- 找到匹配池后即停止向上查找；若遍历到根仍未找到，则**回落到直接父组件的默认复用池**。
- 子组件可被外层池整体接纳（包括其内部嵌套的可复用子组件），无需为每层独立配置池。

### 8.5 使用规则

- `getReusableInfo` 和 `preRender` **仅在全局复用池实例上可用**，不能在默认复用池的自定义组件上调用。
- 使用 `'shared'` 模式时，只要拥有组件类的任何实例存在，池就会持续存在，回收组件可能累积，**应通过 `maxCount` 控制内存**。
- **不建议在 `aboutToRecycle` 中修改会触发重新渲染的状态变量**，因为组件此时正从 UI 树移除。

### 8.6 全局复用池 vs 默认复用池

| 类别 | 默认复用池 | 全局复用池 |
| --- | --- | --- |
| 声明方式 | 无需声明，父组件自动维护 | 在 `@Component` / `@ComponentV2` 上显式配置 |
| 跨分支复用 | 不支持 | 支持 |
| 池共享 | 每个父实例独立持池 | `shared` 模式下同组件类所有实例共享一池 |
| 缓存大小控制 | 不支持 | 支持（按组件 / 按 `reuseId`） |
| 预渲染 | 不支持 | 支持 |
| 池状态查询 | 不支持 | 支持 |
| 内存管理 | 池生命周期与父实例绑定 | `shared` 池持续至最后一个拥有实例销毁；`perInstance` 池与实例绑定 |
| 最低 API 版本 | API 10（V1）/ API 18（V2） | API 26 |

# 实况窗正式权限申请材料模板

## 场景描述模板

```markdown
接入场景：[具体场景描述，例如：用户打车后，通过实况窗通知展示接驾进展、行程进展等信息]

展示时机：[说明实况窗出现的触发条件，例如：用户提交即时出行订单后，或预约订单开始前30分钟]

展示节点：[列出所有状态节点，用逗号分隔，例如：呼叫司机、司机赶来、司机到达上车点、前往目的地、到达目的地-待支付、到达目的地-已支付]
```

## 各场景描述示例

### 打车出行场景

```markdown
接入场景：用户打车后，通过实况窗通知展示接驾进展、行程进展等信息

展示时机：用户提交即时出行订单后，或预约订单开始前30分钟

展示节点：呼叫司机、司机赶来、司机到达上车点、前往目的地、到达目的地-待支付、到达目的地-已支付
```

### 外卖配送场景

```markdown
接入场景：用户下单外卖后，通过实况窗展示商家接单、骑手配送、送达等配送进展信息

展示时机：用户成功提交外卖订单后

展示节点：待支付、商家待接单、商家已接单、骑手取货中、骑手已到店、骑手送货中、已送达/待取餐
```

### 航班出行场景

```markdown
接入场景：用户预订航班后，通过实况窗展示航班值机、登机、起飞、抵达等行程进展信息

展示时机：计划起飞前3个小时开始展示实况窗

展示节点：未值机、已值机、开始登机、催促登机、已登机、已起飞、已抵达、延误、取消、登机口变更
```

### 高铁出行场景

```markdown
接入场景：用户预订高铁票后，通过实况窗展示车次信息、检票口、出发到达时间等行程信息

展示时机：计划出发前1个小时开始展示实况窗通知

展示节点：计划出发、高铁晚点（动态更新）、临时停车、高铁取消、已到达
```

### 即时配送场景

```markdown
接入场景：用户购买商品后，通过实况窗展示快递配送进度、取件提醒等信息

展示时机：用户订单生成后8小时内的配送场景

展示节点：待支付、商家待接单、商家已接单、骑手取货中、骑手已到店、骑手送货中、已送达/待取餐
```

## 小程序场景额外材料模板

如果应用内支持其他应用的小程序，需提供以下证明材料：

### 沟通对齐证明模板

```markdown
【小程序沟通对齐证明】

小程序名称：[小程序名称]
小程序客户端：[小程序所属应用名称]
合作场景：[具体场景描述]

双方约定：
1. 客户端不会对开发者应用内其小程序产生的任务进行实况窗通知
2. 实况窗通知仅由开发者应用负责推送
3. 避免同一任务多端推送实况窗，确保用户体验一致性

沟通日期：[YYYY-MM-DD]
沟通方式：[邮件/会议/电话等]
参与人员：[双方负责人姓名及联系方式]

小程序客户端确认签字：________________
开发者应用确认签字：________________
```

### 策略变更预案模板

```markdown
【策略变更预案】

小程序名称：[小程序名称]
预案场景：小程序客户端策略发生变更时的应对方案

变更监控：
- 定期检查小程序客户端的实况窗推送策略（每月一次）
- 与小程序客户端保持沟通渠道畅通
- 及时获取客户端版本更新通知

应对措施：
1. 短期方案：立即联系小程序客户端协商，明确双方推送边界
2. 中期方案：调整开发者应用的实况窗推送逻辑，避免冲突
3. 长期方案：评估是否需要停止该小程序场景的实况窗推送

联系人：[预案负责人姓名]
联系方式：[电话/邮箱]
预案更新周期：每季度review一次
```

## 接入方案截图制作要求

### 截图内容要求
- **卡片态**：每个状态节点的卡片展示效果
- **胶囊态**：状态栏胶囊展示效果
- **锁屏态**：锁屏界面展示效果
- **展示时机**：每个节点的触发时机说明
- **特殊场景**：取消订单等特殊场景的展示效果

### 截图格式要求
- 文件格式：PNG或JPG
- 文件大小：不超过3MB
- 图片分辨率：建议1920x1080或更高
- 图片命名：场景名_节点名_展示形式.png

### 截图布局建议
建议将所有内容整合在一张图片中：
- 上部：各状态节点的卡片效果（横向排列）
- 中部：胶囊效果和锁屏效果（并列展示）
- 下部：展示时机说明和特殊场景方案
- 侧边：可添加简要说明文字

## 材料提交清单

- [ ] 场景描述文本（不少于50字）
- [ ] 接入方案截图（PNG/JPG格式，<3MB）
- [ ] 自检清单确认文档
- [ ] 小程序沟通证明（如适用）
- [ ] 策略变更预案（如适用）
- [ ] 应用月活数据证明
- [ ] 应用上架证明

## 注意事项

1. 所有材料需真实有效，不得虚假填报
2. 截图必须来自已通过调试验证的真实效果
3. 场景描述需详细具体，避免模糊表述
4. 特殊场景方案需充分考虑用户体验
5. 小程序证明需双方签字确认
6. 材料提交后等待审核，期间不得修改应用实况窗功能

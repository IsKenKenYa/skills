# Camera Kit 常见故障场景案例库

## 概述

**文档用途：** 按错误码/故障现象关键词检索，提取"可能原因（根因）"与"解决方案（修复建议）"。

**适用场景：** 调用相机接口报`7400xxx`、相机黑屏/闪退/调起失败、预配置与参数异常、视频会议中相机异常、手电筒功能失效等。

## 前置知识

### 核心概念

- **相机权限**：`ohos.permission.CAMERA`，必须在`module.json5`中声明并动态申请
- **会话生命周期**：`beginConfig` → `addInput/addOutput` → `commitConfig` → `start` → `stop`
- **前后台切换**：在`onPageShow`中重新初始化，`onPageHide`中释放资源
- **异步操作**：拍照需等待`on('captureReady')`事件

### 硬件与接口限制

- **能力查询优先**：使用`getSupportedOutputCapability`获取设备支持的分辨率
- **手电筒与闪光灯互斥**：不能同时开启
- **状态机约束**：会话状态变化需遵循严格时序

## 核心故障案例

### 案例1：调用 preconfig 接口报错 7400201

- **错误码：** 7400201（SERVICE_FATAL_ERROR）
- **故障现象：** 调用`VideoSession.preconfig`接口时抛出7400201错误
- **涉及接口：** `VideoSession.preconfig`
- **可能原因：** 预配置参数不合法或设备不支持
- **解决方案：** 检查预配置参数，确保设备支持该配置

### 案例2：前置摄像头点击闪光灯应用闪退（7400102）

- **错误码：** 7400102（OPERATION_NOT_ALLOWED）
- **故障现象：** 前置摄像头调用闪光灯接口导致应用闪退
- **涉及接口：** `cameraInput.setFlashMode`
- **可能原因：** 前置摄像头不支持闪光灯功能
- **解决方案：** 前置摄像头场景禁用闪光灯功能

### 案例3：setFrameRate 设置帧率参数异常（7400101 / 7400110）

- **错误码：** 7400101（INVALID_ARGUMENT）或7400110（UNRESOLVED_CONFLICTS）
- **故障现象：** `setFrameRate`设置不支持的帧率或与其它配置冲突
- **涉及接口：** `previewOutput.setFrameRate`
- **可能原因：** 帧率超出设备支持范围或与其它流配置冲突
- **解决方案：** 使用`getSupportedFrameRates`获取支持的帧率范围

### 案例4：连续两次调用拍照方法报错 7400102

- **错误码：** 7400102（OPERATION_NOT_ALLOWED）
- **故障现象：** 连续快速调用`capture`方法报错
- **涉及接口：** `photoOutput.capture`
- **可能原因：** 上次拍照操作未完成，触发并发限制
- **解决方案：** 使用`on('captureReady')`监听拍照就绪状态

### 案例5：相机界面黑屏排查（综合）

- **涉及场景：** 多种黑屏情况综合分析
- **可能原因：**
  - 预览流未正确配置
  - surfaceId无效
  - 分辨率不支持
  - 相机服务异常
- **解决方案：** 按排查流程逐步定位

### 案例6：双进程同时打开相机报错 7400107

- **错误码：** 7400107（CONCURRENT_STREAMS_EXCEED_LIMIT）
- **故障现象：** 两个应用同时打开相机，后打开的应用报错
- **涉及接口：** `cameraManager.createCameraInput`
- **可能原因：** 相机资源被其它进程占用
- **解决方案：** 实现进程间相机资源协调机制

### 案例7：连续两次调用 beginConfig 报错 7400105

- **错误码：** 7400105（SESSION_CONFIG_LOCKED）
- **故障现象：** 调用`beginConfig`后不调`commitConfig`直接再次调用`beginConfig`报错
- **涉及接口：** `session.beginConfig`
- **可能原因：** 会话处于CONFIG_INPROGRESS状态
- **解决方案：** `beginConfig`后必须调用`commitConfig`才能再次配置

### 案例8：会话未配置就启动报错 7400103

- **错误码：** 7400103（SESSION_NOT_CONFIG）
- **故障现象：** 创建空session后直接调用`start()`报错
- **涉及接口：** `session.start`
- **可能原因：** 会话未经过配置流程
- **解决方案：** 按`beginConfig`→添加流→`commitConfig`→`start`顺序调用

### 案例9：会话未运行就拍照报错 7400104

- **错误码：** 7400104（SESSION_NOT_RUNNING）
- **故障现象：** `commitConfig`成功但未调用`start`就进行拍照操作报错
- **涉及接口：** `photoOutput.capture` / `session.setFlashMode`
- **可能原因：** 会话未启动就执行需要运行状态的操作
- **解决方案：** `commitConfig`后必须调用`start`才能进行拍照等操作

### 案例10：重复添加相同输出流报错 7400110

- **错误码：** 7400110（UNRESOLVED_CONFLICTS）
- **故障现象：** 重复添加相同的PreviewOutput到session报错
- **涉及接口：** `session.addOutput`
- **可能原因：** 同一输出流不能重复添加
- **解决方案：** 添加前检查是否已添加，如需替换先移除再添加

### 案例11：使用不支持的分辨率初始化相机

- **错误码：** 7400101（INVALID_ARGUMENT）
- **故障现象：** 使用1:1分辨率或不支持的比例初始化相机报错
- **涉及接口：** `createPreviewOutput` / `createPhotoOutput`
- **可能原因：** 指定的分辨率比例在当前设备上不支持
- **解决方案：** 使用`getSupportedOutputCapability`获取支持的分辨率列表

### 案例12：metadataOutput 异常报错 7400201

- **错误码：** 7400201（SERVICE_FATAL_ERROR）
- **故障现象：** 注册`metadataOutput.on('metadataObjectsAvailable')`事件监听时报错
- **涉及接口：** `metadataOutput.on`
- **可能原因：** metadataOutput内部错误或服务异常
- **解决方案：** 确保在session配置完成后注册监听，检查设备支持情况

### 案例13：切换前后置摄像头失败

- **错误码：** 7400201（SERVICE_FATAL_ERROR）
- **故障现象：** Session更换CameraInput时调用`removeInput`报错
- **涉及接口：** `session.removeInput`
- **可能原因：** 切换时未先释放相机流就直接移除输入
- **解决方案：** 切换摄像头前必须先释放当前相机的输入流

### 案例14：重复调用 stop 报错 7400102

- **错误码：** 7400102（OPERATION_NOT_ALLOWED）
- **故障现象：** 调用相机关闭接口`stop`两次，第二次报错
- **涉及接口：** `session.stop`
- **可能原因：** 第一次`stop`已将会话停止
- **解决方案：** `stop`调用后做好状态标记，避免重复调用

### 案例15：createCameraInput 时序错误

- **错误码：** 7400102（OPERATION_NOT_ALLOWED）
- **故障现象：** 在错误的时序下调用`createCameraInput`报错
- **涉及接口：** `cameraManager.createCameraInput`
- **可能原因：** 接口调用时序不正确，如相机刚关闭就立即创建
- **解决方案：** 确保相机完全关闭后再等待一小段时间才创建新的CameraInput

### 案例16：手电筒与闪光灯模式冲突

- **错误码：** 7400102（OPERATION_NOT_ALLOWED）
- **故障现象：** 闪光灯模式开启时尝试打开手电筒报错
- **涉及接口：** `cameraManager.setTorchMode` / `session.setFlashMode`
- **可能原因：** 闪光灯模式和手电筒模式互斥
- **解决方案：** 打开手电筒前先关闭闪光灯模式

### 案例17：未声明 CAMERA 权限

- **错误码：** 202 / 7400102
- **故障现象：** 应用未声明`ohos.permission.CAMERA`权限，调用相机相关接口报错
- **涉及接口：** `createCameraInput`
- **可能原因：** `module.json5`中未声明相机权限或运行时未动态申请
- **解决方案：** 在`module.json5`中声明权限并运行时动态申请

### 案例18：双路预览黑屏

- **错误码：** 7400101（INVALID_ARGUMENT）
- **故障现象：** 双路预览代码运行黑屏
- **涉及接口：** `cameraManager`相关接口
- **可能原因：** 创建两个预览输出时参数配置异常
- **解决方案：** 检查两个预览输出是否使用相同的surfaceId

### 案例19：录屏黑屏

- **错误码：** 7400201（SERVICE_FATAL_ERROR）
- **故障现象：** 调用摄像头服务失败，导致录屏黑屏
- **涉及接口：** 摄像头服务调用
- **可能原因：** 摄像头服务异常或会话生命周期管理问题
- **解决方案：** 检查session是否在正确时机创建和释放

### 案例20：接口执行顺序错误（通用）

- **错误码：** 7400102（OPERATION_NOT_ALLOWED）
- **故障现象：** 在不正确的时机调用API报错
- **涉及接口：** 多种接口组合
- **可能原因：** Camera Kit对接口调用顺序有严格要求
- **解决方案：** 严格遵循Camera Kit接口调用时序

### 案例21：安全相机视频编码失败

- **错误码：** 7400201（SERVICE_FATAL_ERROR）
- **故障现象：** Native使用AVCodec视频编码场景，安全相机功能异常
- **涉及接口：** `addOutput`
- **可能原因：** 安全相机需要配合Device Security Kit使用
- **解决方案：** 安全相机必须在支持TEE的设备上使用

### 案例22：会议中接听电话后相机异常

- **错误码：** 7400201（SERVICE_FATAL_ERROR）
- **故障现象：** 会议中接听电话后再回到会议，摄像头采集异常
- **涉及接口：** `OH_CaptureSession_CommitConfig`
- **可能原因：** 前台状态更新和查询时间差问题
- **解决方案：** 在`onPageShow`中重新初始化相机会话

### 案例23：设备频繁切换

- **错误码：** 7400111（DEVICE_FREQUENTLY_SWITCHED）
- **故障现象：** 短时间频繁切换前后摄像头，触发限制
- **涉及接口：** `createCameraInput(open/close)`
- **可能原因：** 短时间内切换次数超过系统限制
- **解决方案：** 在UI层限制用户切换摄像头的频率

### 案例24：相机镜头收回

- **错误码：** 7400112（CAMERA_LENS_RETRACTED）
- **故障现象：** 折叠/跌落保护导致镜头收回，相机无法打开
- **涉及接口：** `cameraInput.open`
- **可能原因：** 折叠屏设备折叠状态变化触发物理镜头收回
- **解决方案：** 监听折叠状态变化`on('foldStatusChange')`

### 案例25：三折叠手机录像黑屏

- **错误码：** 7400201（SERVICE_FATAL_ERROR）
- **故障现象：** 三折叠手机调用前置摄像头录像时预览黑屏
- **涉及接口：** `addOutput`
- **可能原因：** 三折叠设备上640*480分辨率不支持录像
- **解决方案：** 使用设备支持的录像分辨率

## 故障排查流程

### 流程1：相机打开失败排查

```
相机打开失败
│
├─ Step 1: 检查相机权限
│   ├─ 确认 module.json5 中已声明 ohos.permission.CAMERA
│   └─ 确认运行时已通过 requestPermissionsFromUser 申请权限
│
├─ Step 2: 检查相机设备状态
│   ├─ 相机是否被其它应用占用 → 7400107
│   ├─ 相机是否被安全策略禁用 → 7400108
│   └─ 相机是否支持当前操作
│
├─ Step 3: 检查相机服务
│   ├─ CameraService 是否正常运行
│   └─ IPC 通信是否正常
│
├─ Step 4: 根据错误码定位
│   ├─ 7400107: 相机冲突 → 释放其它应用的相机占用
│   ├─ 7400102: 权限不足 → 检查权限申请流程
│   ├─ 7400108: 设备禁用 → 检查安全策略配置
│   ├─ 7400109: 设备被抢占 → 等待高优先级应用释放
│   └─ 7400201: 服务崩溃 → 重启相机服务或设备
│
└─ Step 5: 环境检查
    ├─ 设备类型是否支持该相机操作
    └─ 系统版本是否满足要求
```

### 流程2：会话配置失败排查

```
会话配置失败
│
├─ Step 1: 检查配置时序
│   ├─ 是否先调用 beginConfig
│   ├─ 添加输入输出流是否在 beginConfig 之后、commitConfig 之前
│   └─ 是否调用了 commitConfig
│
├─ Step 2: 根据错误码定位
│   ├─ 7400103: 会话未配置 → 确保调用了 beginConfig 和 commitConfig
│   ├─ 7400105: 配置已锁定 → commitConfig 后才能开始新配置
│   └─ 7400110: 流冲突 → 检查是否有重复添加的流
│
├─ Step 3: 检查输入输出流可用性
│   ├─ canAddInput / canAddOutput 返回是否为 true
│   └─ 输入输出流是否被其它 session 占用
│
└─ Step 4: 解决方案
    ├─ 理顺调用时序
    ├─ 使用 canAddInput/canAddOutput 判断后再添加
    └─ 重复配置前先 commitConfig
```

### 流程3：拍照/预览失败排查

```
拍照/预览失败
│
├─ Step 1: 检查会话状态
│   ├─ 会话是否已调用 start → 7400104
│   └─ 会话是否处于正常运行状态
│
├─ Step 2: 检查拍照调用方式
│   ├─ 是否连续调用 capture → 使用 on('captureReady') 等待
│   ├─ capture 参数是否正确
│   └─ photoOutput 是否正确初始化
│
├─ Step 3: 检查预览流
│   ├─ surfaceId 是否有效
│   ├─ XComponent 是否已创建
│   └─ 预览分辨率是否支持
│
├─ Step 4: 根据错误码定位
│   ├─ 7400104: 会话未运行 → start 后再拍照
│   ├─ 7400102: 接口执行顺序错误 → 检查时序
│   └─ 7400201: 服务异常 → 检查相机服务状态
│
└─ Step 5: 特殊场景
    ├─ 折叠屏切换后是否重新初始化
    └─ 前后台切换后是否重新初始化
```

### 流程4：手电筒问题排查

```
手电筒问题
│
├─ Step 1: 检查闪光灯状态
│   ├─ 当前是否为前置摄像头 → 前置不支持闪光灯
│   └─ FlashMode 是否已开启 → 互斥关系
│
├─ Step 2: 检查设备支持
│   ├─ isTorchSupported 返回是否为 true
│   └─ isTorchModeSupported(TorchMode.ON) 返回是否为 true
│
├─ Step 3: 正确的调用顺序
│   ├─ 先关闭 FlashMode（setFlashMode(FLASH_MODE_CLOSE)）
│   └─ 再打开手电筒（setTorchMode(TorchMode.ON)）
│
├─ Step 4: 根据错误码定位
│   └─ 7400102: 操作不允许 → 检查闪光灯状态和调用顺序
│
└─ Step 5: 解决方案
    ├─ 前置摄像头隐藏/禁用闪光灯按钮
    ├─ 打开手电筒前关闭闪光灯模式
    └─ 添加 try-catch 防止异常
```

### 流程5：权限问题排查

```
权限问题
│
├─ Step 1: 检查静态声明
│   └─ module.json5 的 requestPermissions 中是否有 ohos.permission.CAMERA
│
├─ Step 2: 检查动态申请
│   ├─ 是否调用 requestPermissionsFromUser
│   └─ 用户是否授权
│
├─ Step 3: 根据日志定位
│   ├─ errorReason: 2 → 未声明权限
│   ├─ result: [-1] → 用户拒绝授权
│   └─ state: -1 → 无法再弹窗（权限被永久拒绝）
│
├─ Step 4: 解决方案
│   ├─ 声明权限 → 修改 module.json5
│   ├─ 申请权限 → 调用 requestPermissionsFromUser
│   ├─ 用户拒绝 → 引导用户去设置中开启
│   └─ 永久拒绝 → 提示用户手动开启权限
│
└─ Step 5: 特殊场景
    └─ 二次申请 → 使用 requestPermissionOnSetting
```

### 流程6：服务崩溃排查

The width and height of viewcontrol do not match the width and height supported by the camera.` - **可能原因：** `ViewControl` 的 `width`/`height` 与 `XComponent` 不一致；`start` 根据设置宽高匹配最接近的相机分辨率，未匹配到时返回 1000500001。 - **解决方案：** `ViewControl` 设置的宽高比例与 `XComponent` 组件宽高保持一致。 --- ### 案例扩展2：拍照弹出「暂无可用打开方式」 - **错误码：** 无 - **故障现象：** 拍照时弹出「暂无可用打开方式」提示。 - **涉及接口：** 通过系统意图 直接调用相机（非推荐方式） - **可能原因：** 系统未找到能处理拍照请求的应用 —— 设备未安装系统相机应用、模拟器无完整相机功能，或默认相机应用不支持该意图。 - **解决方案：**  1. 改用官方 `@kit.ImageKit` 能力（`PhotoView` 组件或 `PhotoAccessHelper`）管理拍照流程，确保与系统相机兼容。  2. 在真机上确认系统相机应用已安装并启用（模拟器相机功能可能不完整）。  3. 即使 `module.json5` 声明了 `ohos.permission.CAMERA`，仍需运行时用 `abilityAccessCtrl` 动态申请，否则相机功能可能被系统阻止。 --- ### 案例扩展3：无法读取下载目录下已保存照片 - **错误码：** 无明确相机错误码（主体属媒体库 / 文件管理） - **故障现象：** 无法读取下载目录（公共目录）下已保存的照片。 - **涉及接口：** `@kit.FileKit` 的 `FileManager.getPublicDirectory`(Downloads) / `FileAccessHelper`；权限 `ohos.permission.READ_IMAGEVIDEO` / `WRITE_IMAGEVIDEO` - **可能原因：**  - 未动态申请 `READ_IMAGEVIDEO` / `WRITE_IMAGEVIDEO`（`user_grant`，须动态申请并经用户授权）。  - 文件保存路径不正确或未成功写入。  - 直接使用硬编码路径访问，受文件系统沙箱机制限制，应用无相应权限无法访问公共区域。 - **解决方案：**  1. 动态申请 `READ_IMAGEVIDEO` / `WRITE_IMAGEVIDEO` 权限，并补全权限申请弹窗逻辑。  2. 用 `FileManager.getPublicDirectory`（指定目录类型为 Downloads）确认公共下载目录路径。  3. 读取目录文件列表用 `FileAccessHelper` / `FileManager` 接口扫描访问，避免硬编码路径。
